## What I got wrong (4 things)

**1. I compared the wrong file classes and nearly reported 51 phantom orphans.** Comparing
all 81 deployed files against the repo's 61 distinct basenames gives 32 apparent orphans. My
first instinct was that these were stale copies left by the flat deploy, which would have
been a serious and completely false claim. Every one of the 32 is a `.service` that
self-declares:

```text
$ head -3 ~/.config/containers/systemd/ao-sales-db.service
# Automatically generated by /usr/libexec/podman/quadlet
#
# /ALWAYSON/quadlet/sales/ao-sales-db.container
```

*Reason I got it wrong:* I compared **outputs** against **sources** without classifying them.
The `.service`/`.timer`/`.path` files are products of the generator, not deploy residue.
The comparison is only meaningful when restricted to source-typed files
(`.container`/`.network`/`.volume`/`.build`).

**2. I named the wrong generator.** I wrote `systemd-container-generator`, which does not
exist on this host. The real one is Podman's `/usr/libexec/podman/quadlet`, as the file's
own header states.

**3. I guessed a YAML key and read the resulting empty list as a clean result.** Stage 40
printed nothing, and the shape of that nothing was indistinguishable from "no vendor blobs
to remove". The key is `vendor_binaries`, not `binaries`/`appimages`:

```text
$ python3 -c "import yaml;print(sorted(yaml.safe_load(open('config/build-update/vendor-binaries.yaml'))))"
['measured_on', 'measured_utc', 'schema_version', 'vendor_binaries']
```

*Reason:* a parser returning zero and a measurement returning zero look identical. The
script now hard-fails with `MANIFEST SHAPE CHANGED` if `vendor_binaries` is absent, and has
an explicit `NO MANIFEST at ...` branch so an absent file can never again read as a clean
zero.

**4. My own staged edits left the file broken twice.** An insert landed a duplicated `fi`
(syntax error), and my cleanup of trailing orphan lines over-deleted the flatpak block and
the stage-30 warning that belonged to stage 30. Both were caught by `bash -n` plus reading
the actual output rather than trusting the edit succeeded. *Lesson: after a multi-step
staged edit, re-run the syntax check and re-read the produced output; the editor reported
success for both broken states.*

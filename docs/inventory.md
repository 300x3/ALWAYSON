## How to read these tables

| Term | Meaning |
|---|---|
| `digest sha256:...` | Immutable. Cannot drift without an explicit edit. Safe. |
| `NOT PINNED (floating tag)` | **A finding.** The tag can move under the unit. |
| `local build` | Built on this host. A rebuild changes the digest and fails the unit until re-pinned. |
| `not pinned` | An ordinary package with no immutability guarantee. |
| `UNATTENDED` | Upgrades itself with no human involvement. |
| `manual` | Waits for an operator decision. |

## Keeping this current

The inventory is generated, so it is never hand-edited. What it needs is
to be *regenerated* at the right moments:

| When | Action |
|---|---|
| After any image promotion | `./scripts/build-update/inventory-system.sh --markdown --out docs/inventory.md` |
| After any `apt upgrade` | same |
| After a driver or kernel change | same — the OS table flags matrix drift automatically |
| Weekly | `inventory-refresh.timer` regenerates it into a working copy for review |

The weekly timer regenerates the file and writes it to a working copy for
review, so drift shows up as a diff instead of being discovered later. It
does **not** install anything, and it does not touch a running service.
